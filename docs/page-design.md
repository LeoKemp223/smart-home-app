# 智能家居 APP 页面设计文档

> 版本：v0.2（2026-09-03，同步后端 `docs/api/app-api.md` v0.2 后更新：SSE 实时推送上线、控制改投递语义、别名/解绑接口可用）
> 配套工程：smart-home-app（uni-app + Vue 3 + TypeScript，跨 H5 / 微信小程序 / App）
> 后端：ZIOT Console（API 详见 [ziot-app-integration.md](./ziot-app-integration.md)）
> 设计参考：米家、涂鸦智能（Tuya）、华为智慧生活、Aqara Home 的通用信息架构

---

## 1. 设计原则与约束

### 1.1 后端能力约束（决定页面设计边界）

页面设计严格对齐 ZIOT 当前 API 能力，避免设计出后端撑不起的功能：

| 后端能力 | 现状 | 设计约束 |
|---|---|---|
| 用户体系 | 手机号+密码，开放注册 | 登录/注册极简，无第三方登录、无验证码登录 |
| 设备绑定 | 扫码/输码绑定，一码多绑（家庭共享） | 无「配网」流程（设备由工厂/卖家预配置），绑定即用 |
| 设备状态 | 列表快照 + shadow 全集 + **SSE 实时事件流**（属性更新/上下线推送，20s 心跳保活） | 前台 SSE 实时刷新，轮询 3–5s 仅作兜底；断线重连后先拉列表+shadow 对齐 |
| 设备控制 | **投递语义**：`commands:sync` 几十毫秒即返回终态（success=已送达 Broker，≠设备已执行） | 控制按钮 loading 态极短；「已发送」文案；执行确认以 SSE/shadow 回读为准 |
| 设备管理 | 改别名（PATCH alias，仅自己可见）+ 解绑（DELETE，软删除）均已支持 | 设置页重命名/解绑入口可进 P0 |
| 无后端支持 | 房间/场景/自动化/定时/离线消息推送/家庭组管理/App 端设备日志 | 相关页面只做 UI 占位或延后（见 §6 缺口） |

### 1.2 通用设计原则

1. **一屏一焦点**：首页看状态、设备页做控制、我的页管账号，不混排。
2. **容忍最终一致**：设备状态以 SSE 推送 + shadow 快照为准（轮询兜底）；控制后「已发送 → SSE/shadow 回读确认」，不信任本地假设。
3. **平台适配**：H5/小程序无原生导航能力差异，统一用自定义导航栏（工程已是 `navigationStyle: custom`）。
4. **深色模式**：uni.scss 已有主题变量机制，页面色值全部走变量，预留 dark 主题。

## 2. 信息架构与导航

### 2.1 底部 TabBar（3 Tab）

```
┌─────────────────────────────────────────────┐
│                                             │
│              页面内容区                       │
│                                             │
├──────────────┬──────────────┬───────────────┤
│   🏠 首页     │    ＋ 添加    │    👤 我的     │
│  (设备总览)    │   (设备添加)   │   (账号设置)   │
└──────────────┴──────────────┴───────────────┘
```

> 中间「添加」放 Tab 是国内智能家庭 APP 常见做法（涂鸦/华为均有突出添加入口）；也可改为首页右下角 FAB + 2 Tab，v0.1 先按 3 Tab。

### 2.2 页面地图（Page Map）

```
TabBar
├── 首页 pages/home
│   ├── → 设备控制页 pages/device/detail?type=…
│   │     ├── → 设备日志/上报记录 pages/device/logs
│   │     └── → 设备设置 pages/device/settings
│   ├── → 消息中心 pages/messages        [P1 占位]
│   └── → 扫码绑定（Tab2 或首页入口）
├── 添加 pages/add
│   ├── 扫码绑定（uni.scanCode）→ 绑定确认页 pages/add/confirm
│   └── 手动输码 pages/add/manual
└── 我的 pages/mine
    ├── 个人资料 pages/mine/profile       [P1，依赖 user 字段]
    ├── 修改密码 pages/mine/password     [P1，依赖改密接口]
    ├── 关于/版本 pages/mine/about
    └── 设置 pages/mine/settings         [P1]
登录态前置页
└── 登录/注册 pages/login                 （未持有效令牌时进入）
```

### 2.3 页面清单与优先级

| 优先级 | 页面 | 路径 | 说明 |
|---|---|---|---|
| **P0** | 登录/注册 | `pages/login` | 含登录+注册双模式切换 |
| **P0** | 首页（设备总览） | `pages/home` | 核心页面 |
| **P0** | 设备控制页 | `pages/device/detail` | 按产品模板渲染控制面板 |

| **P1** | 个人资料/改密/设置 | `pages/mine/*` | 依赖后端接口 |
| **P2** | 房间管理/场景/自动化 | — | 后端无支持，延后 |

## 3. P0 页面详细设计

### 3.1 登录/注册页 `pages/login`

**目的**：手机号+密码注册/登录，进入 APP 的唯一入口。

**布局**（参考米家/涂羌登录页：品牌区 + 表单区 + 协议区）：

```
┌────────────────────────────┐
│        App Logo + 名称       │  品牌区
│                            │
│  ┌──────────────────────┐  │
│  │ +86 │ 139 1234 5678  │  │  手机号输入（11位校验）
│  └──────────────────────┘  │
│  ┌──────────────────────┐  │
│  │ 密码（8-20位，字母+数字）│  │  密码输入（可见性切换）
│  └──────────────────────┘  │
│  ┌──────────────────────┐  │  仅注册模式显示
│  │ 昵称（选填）           │  │
│  └──────────────────────┘  │
│  ┌──────────────────────┐  │
│  │       登  录          │  │  主按钮（loading 态）
│  └──────────────────────┘  │
│      登录 / 注册 切换链接      │  Tab 或底部文字链
│                            │
│  ☑ 已阅读并同意《用户协议》     │  协议勾选（未勾选点击登录时弹提示）
│     《隐私政策》              │
└────────────────────────────┘
```

**信息与交互**：

| 元素 | 内容 | 逻辑 |
|---|---|---|
| 模式切换 | 登录 ⇄ 注册 | 注册多一个「昵称（选填）」字段 |
| 手机号输入 | 11 位大陆手机号 | 前端正则 `/^1[3-9]\d{9}$/`；不满足置灰主按钮 |
| 密码输入 | 8–20 位 | 后端规则已确认：**8-128 位**（无强制字符组合）；前端可保守按 8–20 位 + 字母数字前置校验；眼睛图标切换明文 |
| 主按钮 | 登录/注册 | 点击时校验协议勾选；请求中 loading + 防重复提交 |
| 成功 | 存 token → reLaunch 首页 | access/refresh token 落 uni.storage |
| 失败 | Toast 错误信息 | 手机号已注册 / 密码错误等按错误码映射文案 |
| 协议 | 用户协议/隐私政策链接 | 小程序发布合规必备；P0 可先用静态页 |

**状态**：无网络重试、请求失败 Toast、按钮 loading。

### 3.2 首页（设备总览）`pages/home`

**目的**：一眼看清所有设备的在线状态与核心属性，是使用频率最高的页面。

**布局**（参考米家首页：顶部门景信息 + 消息入口 + 设备宫格 + 添加入口）：

```
┌────────────────────────────┐
│  晚上好，小明        🔔     │  问候语（本地时间）+ 消息入口[P1]
│                            │
│  ┌──────┐ ┌──────┐ ┌──────┐│
│  │ 🌡    │ │ 💡    │ │ ⚡   ││  设备宫格卡片 2列
│  │ 温湿度计│ │ 智能灯 │ │插座  ││  卡片 = 图标 + 名称 + 状态摘要
│  │ 23.6°C │ │ 已关闭 │ │ 在线 ││
│  │ ● 在线  │ │ ○ 离线 │ │     ││  在线绿点/离线置灰
│  └──────┘ └──────┘ └──────┘│
│  ┌──────┐ ┌──────────────┐ │
│  │ ＋    │ │  (空态占位)    │ │  「+」卡片固定在宫格末尾
│  │ 添加设备│ │              │ │
│  └──────┘ └──────────────┘ │
│                            │
│  下拉刷新 · 底部 TabBar      │
└────────────────────────────┘
```

**信息与交互**：

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 顶栏 | 问候语（时段：早上好/下午好/晚上好）+ 用户昵称 | 本地时间 + user.nickname |
| 消息入口 | 🔔 图标，未读红点 | P1 消息中心 |
| 设备卡片 | 设备图标（按产品类型）、名称、在线状态、**核心属性摘要**（取 shadow 快照前 1–2 个关键值，如温度） | `GET /app/devices`（列表自带快照） |
| 添加卡片 | 固定「＋ 添加设备」宫格 | → Tab2 或绑定页 |

交互逻辑：
- **下拉刷新**：重新拉设备列表。
- **实时状态**：全局一条 SSE 连接（`composables/useDeviceEvents`），首页订阅 `device.status.changed` / `device.shadow.updated` 增量刷新卡片；轮询降级为兜底（网络差/SSE 不可用时 `onShow` 拉取 + 页面停留每 5–10s，`onHide` 停）。
- **点击卡片** → 设备控制页；**长按卡片** → 弹 ActionSheet（重命名/解绑/设备设置）。重命名调 `PATCH /app/devices/{id}` 改的是**自己可见的别名 alias**（不改控制台侧设备名），解绑调 `DELETE`——两个接口均已可用。
- **离线设备**：卡片整体置灰 + 「离线」标签，点击仍可进详情页（查看历史快照）。未上线第三态 `unknown` 按「未上线」灰显。
- **空态**（无设备）：居中插画 + 「扫描设备二维码，添加你的第一台设备」+ 添加按钮。
- **未登录**：路由守卫重定向登录页。

### 3.3 设备控制页 `pages/device/detail`

**目的**：单设备的控制中心——看全部属性、发控制命令。

这是**与产品物模型强耦合**的页面：不同产品（灯/插座/温湿度计）控制面板完全不同，需按产品渲染模板。

**布局**（参考米家设备页：状态头卡 + 控制面板 + 历史记录入口 + 设置入口）：

```
┌────────────────────────────┐
│ ← 返回      设备名称     ⋯   │  自定义导航栏（⋯ → 设备页）
│                            │
│ ┌────────────────────────┐ │
│ │      🌡 温湿度计          │ │  状态头卡：大字号展示主属性
│ │      23.6°C  58%        │ │  （每产品定义 1-2 个主展示属性）
│ │      ● 在线 · 刚刚更新    │ │  在线状态 + 数据时间
│ └────────────────────────┘ │
│                            │
│ ┌────────────────────────┐ │
│ │ 控制面板（按产品模板）      │ │  属性控制：开关/滑条/档位…
│ │ ┌────┐ ┌────┐ ┌────┐   │ │  服务调用：按钮（重启等）
│ │ │开  │ │ 关  │ │定时  │  │ │
│ │ └────┘ └────┘ └────┘   │ │
│ └────────────────────────┘ │
│                            │
│ ┌ 上报记录/日志 ──────────→ │ │  [P1] 设备日志页
│ └────────────────────────┘ │
└────────────────────────────┘
```

**信息与交互**：

| 区域 | 内容 | 逻辑 |
|---|---|---|
| 导航栏 | 返回、设备名、⋯（设置入口） | 自定义导航栏 |
| 状态头卡 | 主属性大字号展示 + 在线状态 + 数据更新时间 | `GET /app/devices/{id}/shadow` 初始拉取 + SSE `device.shadow.updated` / `device.status.changed` 实时刷新（轮询 3–5s 兜底） |
| 控制面板 | 按产品物模型渲染：布尔→开关、数值→滑条/步进、枚举→档位按钮、service→动作按钮 | `POST commands:sync` |
| 上报记录入口 | P1 占位 | 依赖后端日志接口（仍缺，见 §6） |

**控制面板渲染规则**（产品配置驱动，非硬编码）：

```ts
// 每个产品一份描述配置（前端维护，identifier 对齐固件物模型）
interface ProductPanel {
  mainStats: string[]              // 头卡主展示属性，如 ['temperature','humidity']
  controls: Array<
    | { type: 'switch';  prop: string; label: string }            // 布尔属性
    | { type: 'slider';  prop: string; label: string; min; max; step }
    | { type: 'enum';    prop: string; label: string; options: {value,label}[] }
    | { type: 'action';  service: string; label: string; confirm?: string } // 服务调用
  >
}
```

**控制交互三步曲**（投递语义下的最终一致交互）：
1. **点击** → 按钮/开关立即进入 loading（**不做乐观翻转**）；
2. **等待** `commands:sync` 返回（**通常几十毫秒**，即投递终态）：`success` → Toast「已发送」→ 等 SSE `device.shadow.updated` 推送（或最多等 2–3s 拉一次 shadow）确认执行；`failed` → Toast 失败原因（`error_message`）；历史遗留 `timeout`/`sent` 状态兜底提示即可；
3. **刷新**：以 shadow/SSE 回读值为准渲染，不信任本地假设。注意 `success` 只代表已送达 Broker，设备可能不执行（离线队列、参数拒绝），UI 文案用「已发送」而非「已执行」。

> 若单产品控制项极多，可分「控制 / 状态」两个分组卡片。

其他：
- **离线设备**：头卡显示离线，控制面板置灰禁用并提示「设备离线，无法控制」。
- **节流**：`onHide` 停轮询/暂停 SSE 分发；控制请求进行中暂停轮询避免闪烁。
- 未知产品（无配置）：兜底渲染 shadow 全部键值只读列表 + 常用「重启」动作。

### 3.4 添加设备页 `pages/add`

**目的**：扫码绑定流程的入口与引导。

**布局**（参考涂鸦/米家添加页：扫码为主体 + 输码兜底）：

```
┌────────────────────────────┐
│ ← 返回     添加设备          │
│                            │
│  ┌──────────────────────┐  │
│  │                      │  │
│  │    📷 扫码区域示意      │  │  主按钮：开始扫码
│  │    （uni.scanCode）    │  │
│  │                      │  │
│  └──────────────────────┘  │
│                            │
│   扫描设备机身的二维码        │  引导文案
│   ┌────────────────────┐   │
│  │   ＋  开始扫码        │   │
│   └────────────────────┘   │
│                            │
│   二维码磨损？手动输入绑定码 → │  次要入口
│                            │
│   绑定步骤说明（折叠）:        │  帮助
│   1. 找到设备机身二维码       │
│   2. 扫码或输入绑定码         │
│   3. 确认设备信息完成绑定      │
└────────────────────────────┘
```

**信息与交互**：

| 元素 | 逻辑 |
|---|---|
| 开始扫码 | `uni.scanCode({ scanType: ['qrCode'] })`；H5 端降级到输码页（浏览器扫码兼容性差） |
| 扫码结果解析 | 取 URL `#` 后的绑定码（见接入文档 §3.2），自动转大写；非 `ziot.asia/b/` 域名的码提示「不是有效的设备码」 |
| 解析成功 | → 绑定确认页 `pages/add/confirm?code=XXX` |
| 手动输码 | → 输码页（P1，v0.1 可与本页合一：弹窗输入） |
| 引导说明 | 静态文案，说明绑定码位置（设备机身/说明书） |

平台注意：
- **H5**：`uni.scanCode` 不可用 → 直接展示输码表单（调用摄像头需要 https + 浏览器支持，v0.1 不做）。
- **小程序**：`uni.scanCode` 原生可用；需要在 manifest/隐私协议声明摄像头用途。
- **App**：原生可用。

### 3.5 绑定确认页 `pages/add/confirm`

**目的**：展示即将绑定的设备信息，确认后完成绑定（防误扫）。

```
┌────────────────────────────┐
│ ← 返回     确认绑定          │
│                            │
│      ┌────────┐            │
│      │  📦    │            │  设备图标
│      └────────┘            │
│      智能温湿度计            │  设备名称（后端返回；无则显示「未知设备」+ 输码改名）
│      产品：pk_xxx           │  产品标识（辅助确认）
│      绑定码：BD7K…FGH       │  脱敏展示（前4后4）
│                            │
│   ┌────────────────────┐   │
│   │     确认绑定         │   │  调 bind 接口，loading
│   └────────────────────┘   │
│                            │
│   绑定后家人也可扫同一张码     │  家庭共享说明文案
│   共同控制这台设备            │
└────────────────────────────┘
┌ toast: 绑定成功 → 跳设备详情 │
└────────────────────────────┘
```

交互：绑定成功 → Toast → `redirectTo` 设备控制页；码无效/已作废 → 明确错误文案（`400001`，服务端防枚举统一提示）并引导联系卖家重新生成。

> ✅ bind 响应字段已确认（设备对象全集）：确认页直接用 `name`（回退「未知设备」）、`product_name`、`online_status`、`shadow_reported` 渲染；绑定时间用 `bound_at`。

### 3.6 设备设置页 `pages/device/settings`

**目的**：设备元信息展示 + 危险操作（解绑）。

```
┌────────────────────────────┐
│ ← 返回     设备设置          │
│                            │
│  设备信息                   │
│  ┌ 别名      客厅的温湿度计 → │  改别名（PATCH alias，仅自己可见；空串清除）
│  ├ 设备名称   智能温湿度计    │  控制台侧名称 name（只读）
│  ├ 设备标识   dk_xxx        │  复制
│  ├ 产品      pk_xxx（产品名）│
│  ├ 在线状态   ● 在线         │
│  ├ 固件版本   v1.0.1        │
│  └ 绑定时间   2026-09-03    │  bound_at
└────────────────────────────┘
│  ┌────────────────────┐    │
│  │    解除绑定（红）     │    │  二次确认弹窗 → DELETE 解绑
│  └────────────────────┘    │
```

交互：
- **改别名**：`PATCH /api/v1/app/devices/{id}`，body `{"alias":"客厅的温湿度计"}`，1-128 位；改的是**自己账号下的别名**（列表/详情展示优先 alias，回退 name），不影响其他家庭成员。
- **解绑**：Modal 二次确认「解绑后将无法控制该设备（不影响其他家庭成员）」→ `DELETE /api/v1/app/devices/{id}`（响应 `{device_id, org_id, unbound_at}`）→ 返回首页并刷新列表。✅ **接口已可用，P0 可放开入口**。
- 家人共享：让家人扫**机身印刷的二维码**即可；App 端暂无查看绑定码的接口（控制台专属，见 §6）。

## 5. 全局规范

### 5.1 路由与登录守卫

- 启动时（App.vue onLaunch）读 storage：无 token → reLaunch 登录页；有 → 直接进首页（首个列表请求若返回 401001 自动刷新，失败再跳登录）。
- 所有 P0 页面注册到 `pages.json` 的 `pages`；tabBar 3 个（custom 自定义 tabBar 或原生 tabBar 均可，v0.1 用原生）。

### 5.2 视觉规范（占位，后续可换设计稿）

| 项 | 规范 |
|---|---|
| 主色 | `#2F6BFF`（智能硬件常用蓝，可配置到 uni.scss `$brand`） |
| 状态色 | 在线 `#00B578` / 离线 `#B8C0CC` / 警告 `#FF8F1F` / 失败 `#FA5151`（参考微信小程序色板） |
| 字号 | 页面标题 34rpx / 卡片主标 30rpx / 正文 28rpx / 辅助 24rpx |
| 圆角 | 卡片 16rpx、按钮 12rpx |
| 间距 | 页面边距 32rpx、卡片间距 24rpx |
| 图标 | 设备图标按产品 icon 字段或内置映射表 |

### 5.3 全局交互规范

- **loading**：页面级（骨架屏）+ 按钮级（按钮内 loading）。
- **错误**：网络错误统一 Toast「网络异常，请重试」；业务错误按错误码映射文案（错误码表已提供：`400001/401001/403001/404001/409001/429001/500001`，`message` 为中文可直连展示）。
- **空态**：首页空设备、日志空列表均有插画+引导按钮。
- **轮询/SSE 纪律**：全局只维护**一条** SSE 连接按 device_id 分发；所有轮询 `onHide` 必停；断线重连后先拉设备列表 + shadow 对齐再收流。

## 6. 页面 ↔ 后端能力映射（2026-09-03 更新）

v0.1 的多数缺口已随 `docs/api/app-api.md` v0.2 落地，当前状态：

| 功能 | 关联页面 | 状态 |
|---|---|---|
| 设备别名 | 首页长按、设备设置 | ✅ `PATCH /app/devices/{id}`（仅自己可见的 alias） |
| 解绑设备 | 设备设置 | ✅ `DELETE /app/devices/{id}`（软删除，不影响家人） |
| 实时状态推送 | 首页/详情 | ✅ SSE `GET /app/events/stream`（shadow 更新 + 上下线 + 20s 心跳；无历史重放，重连先拉齐） |
| 登出（服务端） | 我的/设置 | ✅ `POST /app/auth/logout` 吊销 refresh_token |
| 查看绑定码（App 端） | 设备设置 | ❌ 仍无（控制台专属接口）；家人共享走机身印刷码 |
| 设备日志 | 设备详情入口 | ❌ 无 App 端日志接口（可用 SSE 缓存做本地时间线兜底） |
| 离线消息推送 | 首页 🔔 消息中心 | ❌ 无厂商推送通道（SSE 仅前台） |
| 修改密码 | 我的 | ✅ `POST /app/auth/change-password`（改密即全设备登出，当前设备拿新令牌续用） |
| 房间/场景/自动化/家庭组 | — | ❌ 后端无支持，延后 |
